# PRD 出稿门禁与评审清单

## A. 结构与完整性

- [ ] 15 段齐全，无"待补"占位
- [ ] 文档信息含版本、状态、变更记录、评审记录
- [ ] In Scope 与 Out of Scope 都写了
- [ ] 术语表只列易混概念，且有定义

## B. 可验收性

- [ ] 每条 FR 有编号
- [ ] 每条 FR 有规则 + 边界 + GWT 验收
- [ ] 状态词统一（shall/should/may/must not）
- [ ] 优先级用 MoSCoW 汇总
- [ ] 非功能需求全部有数值
- [ ] 指标有目标值、口径、周期、来源
- [ ] 估算值已标注"估算"
- [ ] 无 baseline 的指标已标注"待建 baseline"

## C. 方案与依赖

- [ ] 至少 3 个候选方案
- [ ] 对比维度覆盖成本、复杂度、体验、风险、上线速度
- [ ] 写清推荐理由与不选其他方案的原因
- [ ] 演进路径有触发条件
- [ ] 依赖分阻塞/并行/可绕过
- [ ] 每个阻塞依赖有最晚就绪时限与替代方案
- [ ] MVP 已切分，能独立验证核心价值

## D. 流程与异常

- [ ] 状态集合完整
- [ ] 状态迁移表覆盖正常与异常
- [ ] 禁止回跳/防重放已说明
- [ ] 异常覆盖空、超大、断网、第三方失败、重复提交、越权、回滚
- [ ] 失败策略明确（fail-open / fail-closed）

## E. 数据、权限、安全

- [ ] 核心实体与关系清楚
- [ ] 关键字段有类型、必填、来源
- [ ] 埋点事件与字段明确
- [ ] 指标公式写清分母
- [ ] 角色 × 功能权限 × 数据权限齐全
- [ ] 密钥管理、审计日志、加密、防重放已覆盖
- [ ] 涉及采集时，数据合规 8 项齐全

## F. 评审闭环

- [ ] 产品/研发/测试/合规四视角均已评审
- [ ] 每条评审有等级、决策、修订落点
- [ ] 拒绝项写明理由
- [ ] 冲突裁决原则已记录
- [ ] 无未闭环的高等级问题

## G. 表达质量

- [ ] 没有"尽量/适当/较好"等不可验收词
- [ ] 没有把方案当需求写
- [ ] 没有编造用户调研数据
- [ ] 没有把厂商宣传语当事实
- [ ] 合规声明已附

## 评审提问清单

给产品：

- 不做这个功能会怎样？
- 哪个指标能证明它成功？
- 本期最想砍掉的是什么？

给研发：

- 哪个依赖会阻塞排期？
- 哪个状态会写错？
- 哪个异常没兜底？

给测试：

- 每条 FR 能否直接写用例？
- 指标口径能否复现？
- 权限能否越权验证？

给合规：

- 采集了什么数据？
- 用户如何关闭/删除？
- 留存多久？谁能访问？
- 是否涉及敏感题材或跨境？
