# Game Product Planning

把"想做一款游戏"拆成可评审的产品方案：先看赛道与竞品，再定定位与差异化，最后落到系统、数值、商业化与合规。

## 何时使用

- 新游戏立项、方向评估
- 竞品分析报告
- 产品结构/功能树
- 核心玩法与系统详设
- 商业化与合规分级

不适用：美术设定集、纯剧情文案、买量投放方案。

## 竞品分析

### 1. 选竞品

选 4 款左右，覆盖不同范式，而不是只选同类。按"拟真度 × 受众广度"或"深度 × 商业化"做象限。

### 2. 定维度

- 定位与品类
- 开发商/发行商/首发时间/平台
- 战场层级/单局时长/上手门槛
- 核心系统：战斗、后勤、经济、外交、AI
- 商业模式：买断/DLC/内购/订阅
- 社区与长线运营
- 视觉与演出
- 优势/短板/产品债

### 3. 写结论

每个竞品回答：

- 它的护城河是什么？
- 它的天花板是什么？
- 它验证了哪条路线？
- 我们不能正面撞的是什么？

### 4. 给启示

按 P0/P1/P2 排序，每条写理由与风险。明确"不建议做什么"。

## 竞品报告骨架

1. 分析背景与目的
2. 竞品选择依据（为什么是这四款）
3. 竞品概览对照
4. 核心维度对比矩阵
5. 分产品分析
6. 关键结论
7. 对自研产品的启示（P0/P1/P2）
8. 数据来源与声明

数据必须标注口径与日期；厂商说法与社区共识分开；不做"好玩程度"评测，聚焦产品能力。

## 立项文档骨架

1. 一句话定义
2. 已确认关键决策（用户拍板项）
3. 定位与差异化
4. 目标用户
5. 核心循环
6. 产品结构/功能树
7. 核心系统详设
8. 内容与长线运营
9. 商业模式
10. 合规风险
11. MVP 与版本规划
12. 未决问题

## 系统拆解（硬核兵棋/策略类参考）

### 核心循环

补给 → 机动 → 交战 → 损耗 → 补充 → 回合推进

### 七大系统

1. 地图：六边形网格、缩放、LOD、地形、迷雾、标注
2. 单位：师/旅级、兵力/装备/补给/疲劳/士气/经验/训练
3. 作战：移动、ZOC、战斗结算、兵种相克、包围、制空
4. 后勤：补给源、补给线、三类资源、运输、断链惩罚
5. 状态：天气、季节、昼夜、地形、道路破坏
6. 指挥官：属性、半径、任命、特性、晋升
7. 回合：阶段顺序、时间轴、历史事件

### 战斗力公式

```text
CF = 兵力规模 × 装备系数 × 士气系数 × 训练系数 × 地形系数 × 补给系数 × 指挥系数
```

各系数建议 0.3-1.5；用乘法便于分系统调参与模式开关。

### 三模式分层

同一套引擎，用四根杠杆分层：

- 规则开关
- 信息密度
- AI 强度
- 单局时长

不要维护三套独立代码。先做硬核模式锁口碑，再用"删减法"做娱乐模式。

## 商业化

- 免费 + 内购时，内容（副本/剧本）是核心变现载体
- 外观皮肤不影响数值
- 便利项设上限，避免 pay-to-win
- 硬核/竞技模式严禁数值付费
- 买断制要评估长线内容与 DLC 节奏

## 合规分级（中国市场）

| 题材 | 敏感度 | 处理 |
|------|--------|------|
| 一战/二战国际战场 | 低-中 | 可首发验证 |
| 抗战 | 高 | 前置法务 + 版号评估 |
| 解放战争 | 极高 | 不作为早期依赖 |
| 抗美援朝 | 高 | 双重敏感，谨慎 |
| 民国军阀混战 | 高 | 脱敏处理 |

硬要求：版号、实名认证、防沉迷、未成年人保护；领土表述遵守一个中国原则；不出现真实国家领导人形象；不歪曲历史。

## MVP 与版本

- V1：核心模式 + 1 个低风险副本 + 核心循环 + 基础留存
- V1.x：内容副本 + 商业化跑通
- V2：中间模式/降槛
- V3：娱乐模式/拉新
- 高敏感题材后置，按合规评估排期

## 未决问题

把"假设"写出来：系统还原度、继承含义、团队/技术栈/工期、美术风格、版号路径。每条给当前假设与验证方式。

## 质量检查

- [ ] 竞品覆盖不同范式，不是同类堆叠
- [ ] 对比维度具体，有数据与日期
- [ ] 结论有"不做什么"
- [ ] 一句话定义清楚
- [ ] 核心循环可闭环
- [ ] 系统之间有耦合，不是功能清单
- [ ] 数值框架可调参
- [ ] 商业化不破坏公平
- [ ] 合规分级写进结构
- [ ] MVP 能独立验证核心价值
- [ ] 未决问题有假设与验证方式
