# Quick Audit — 流程内快速审计

> 源自 engineering-workflow/code-auditor。定位：开发流程中穿插的轻量审计（Quick 档，约 15-30 分钟），只输出高层级、关键问题。需要深度/系统性分析时走本 skill 六步主线（step1~step6）。

## 适用场景

- "快速审一下这次改动 / 这个模块"
- PR 合并前的轻量体检
- 实现完成后的临时质量确认

不适用：全库深度审计、技术债量化评估、架构评审 → 走六步主线。

## 快速流程

1. **探索**：用 Glob/Grep 定位目标范围的关键文件（入口、核心逻辑、配置）
2. **读关键文件**：只读与问题定位相关的代码段，不通读全库
3. **跑现成静态工具**（可用时）：linter、`pytest --cov`、`npm run lint` 等
4. **按下方清单逐项扫查**，只记录有 `file:line` 依据的问题
5. **汇总输出**：按严重度排序，给出 Top 3 优先项

## 六维审计清单（精简版）

| 维度 | 快速扫查点 |
|------|-----------|
| 架构与设计 | 模块边界是否清晰、职责是否混杂、依赖方向是否合理 |
| 代码质量 | 复杂度热点（超长函数/深嵌套）、重复代码、命名不一致、明显 code smell |
| 安全 | 未校验的外部输入、硬编码密钥、OWASP Top 10 常见项、依赖已知漏洞 |
| 性能 | O(n²) 以上热点循环、N+1 查询、明显的资源泄漏（未关闭的连接/句柄） |
| 测试 | 关键路径是否有测试、失败/缺失的测试场景、断言是否有效 |
| 可维护性 | 耦合是否过高、文档/注释是否误导、改动一处是否要改多处 |

## 严重度分级

- **Critical（🔴 阻断）**：安全漏洞、数据损坏、生产崩溃风险 → 立即修
- **High（🔴 高）**：明确 bug、严重设计缺陷、核心路径无测试 → 本迭代修
- **Medium（🟡 中）**：性能隐患、重复代码、耦合过高 → 排期修
- **Low（🟢 低）**：命名、注释、风格 → 顺手修或不修

## 输出格式

```markdown
# Quick Audit Report

## 摘要
- 健康评分：X/10
- 问题数：Critical N / High N / Medium N / Low N
- Top 3 优先项

## 问题清单（按严重度）
### 🔴 Critical / High
- [file:line] 问题描述
  - 影响：...
  - 建议：...（可执行动作，非泛泛观察）
  - 预估：修复耗时 < 1 天 / 1-5 天 / > 5 天

### 🟡 Medium / 🟢 Low
...

## 行动建议
1. Quick wins（< 1 天）
2. 中期改进（1-5 天）
```

## 成功标准

- 每条发现都有 `file:line` 引用
- 每条建议可执行，并附修复成本估计
- 只报告关键问题，不追求穷尽（穷尽 = 深度审计，走六步主线）
