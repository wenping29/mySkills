# 步骤 6：行为等价的代码简化（细则）

在**不改变外部行为**的前提下执行简化，输出简化后代码与变更说明。

- **保持功能**：绝不改动行为、输出、副作用或公共接口，除非用户明确要求
- **遵循项目规范**：匹配既有约定、模式、命名风格与架构预期
- **削减复杂度**：拉平可避免的嵌套、删除冗余抽象、合并重复逻辑、简化条件表达式，选最直接且清晰的实现
- **变量保持有意图**：除非显著提升可读性或复用充分，不引入额外状态
- **优化函数签名与参数传递**；改进命名与逻辑分组，让代码顺序可读
- **默认作用域**：聚焦最近修改的代码，除非用户指定文件/模块/diff
- **验证功能等价**：跑测试或对照行为基线，确认重构前后一致
