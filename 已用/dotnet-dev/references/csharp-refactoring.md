# C# 行为保持重构

蒸馏自源技能 `csharp-refactoring`。重构只改**结构**、不改可观察**行为**；用绑定感知工具完成，再用构建 + 相关测试确认。力度与变更范围成比例：一行局部重命名不需要公共多目标变更的仪式。

## 强制门禁：先分类再验证/编辑

在还原、构建或编辑之前，只读足够仓库上下文对**每个请求操作**分类：

| 被当作"重构"提出的请求 | 分类与动作 |
|---|---|
| 框架或 NuGet 版本变更 | **升级**：移交 dotnet-upgrade 工作流，不在此处编辑 |
| 新能力/开关/端点/层级/行为 | **特性**：移交仓库特性工作流 |
| 阈值/速率/输出/结果变化 | **行为变更**：推迟并移交缺陷修复工作流；可分离的结构操作照做 |
| 收紧/放宽已发布/公共 nullable 注解 | **源契约变更**：声明与 API 记录保持不变，移交 breaking-changes 检查 |

- 混合请求：完成可分离的结构操作，显式推迟行为/契约变更，不得在完成后声称 `No files changed.`
- 全部操作都不属于行为保持重构时，输出固定三段后停止：`Not a behavior-preserving refactor: <原因>` / `No files changed.` / `Next workflow: <工作流>`。
- 绝不通过改测试让未授权的行为变更看起来被保持。

## 只在当前工作区操作

以当前 agent 工作区为边界（Git 仓库用 `git rev-parse --show-toplevel` 解析根；无 Git 时以 cwd 及子目录为边界）。禁止全盘搜索或选同名克隆/worktree/构建输出；命名路径缺失时停下报告，不要猜另一个工作区。

## 按绑定重命名/移动，不按文本

"重命名"悄悄毁代码的头号原因是编辑文本匹配（注释、字符串、无关重载）而非真实**绑定**。先找全部绑定引用，再语义化编辑，按强度选工具：IDE/Roslyn 工作区重构 → C# LSP（`findReferences`、`goToDefinition`、`incomingCalls`、rename code action）→ 分析器 code-fix/Roslynator → 编译器验证编辑（改真实绑定、重建、让编译器报遗漏）。仅当范围可证明极小且每个命中都验证过才用纯查找替换。包含**每个** `partial` 声明；只改生成器输入，绝不改 `*.g.cs` 输出。

## 向既有事实源合并

去重时保留代码/请求声明的所有权方向：`B` 重复 `A` 的实现则保持 `A` 为 canonical、让 `B` 委托，不因"两个方向都能编译"而反转依赖。已发布的重复面保留公共兼容包装，只迁移仓库内可安全移动的调用方。

## 改变编辑动作的决策表

| 情形 | 做 | 绝不做 |
|---|---|---|
| 内联未发布的 internal 透传包装 | 迁移全部绑定引用→删包装→编译抓漏 | 无兼容边界时"为兼容"保留死间接层 |
| 内联/移除已发布/公共包装 | 迁移仓库内调用方，保留 `[Obsolete]` 转发入口（除非明确授权破坏性变更） | 因当前源码调用方已迁移就删除已发布 API |
| 重命名被字符串/反射/DI/配置到达的成员 | 绑定式重命名调用方；用转发 shim 或元数据保留外部观测名，并跑旧名路径 | 为源码新名一致而改写外部/配置名 |
| 提取传不同值的重复逻辑 | 提取算法，各调用方原值原样传入 | 把不同输入/求值顺序/舍入/副作用坍缩成一个调用方的版本 |
| `#if` 或多 TFM 下重命名 | 每个源分支都更新，每个目标框架显式验证 | 把默认目标绿构建当作未构建分支的证据 |
| 合并近似相同的类型 | 只参数化差异值，迁移每个构造点，保留各旧值精确值；internal/未发布且要求合并为一个类型时删除旧声明 | 留下多余别名/静态持有者/工厂/包装类型使合并不完整，或引入新层次/行为 |

## 保留 C# 调用点之外的契约

编译只证明绑定兼容。重命名/移动类型或成员前检查其名字/元数据是否被序列化、反射、DI、配置绑定、源生成器、P/Invoke、`dynamic` 观测：

| 边界 | 必须的动作 |
|---|---|
| 序列化/配置名 | 用仓库既有机制（如 `JsonPropertyName`）保留外部名，同时迁移 C# 调用方；跑聚焦 round-trip/payload 测试 |
| 公共 nullable 注解 | 走分类门禁：保持不变并作为源契约变更移交 |
| 未覆盖的反射/运行时查找 | 不得假定编译干净即安全；保留观测名或停下报告未验证的运行时边界 |

## 按比例验证

- **本地/私有**（方法局部或 `private`、单文件、单 TFM、无公共面、无 partial/generated/`#if`）：树已知绿时免基线，编辑后跑一次最窄构建 + 相关测试，让编译器抓漏。
- **跨边界**（公共/已发布符号、多目标、`#if`/平台分支、partial/生成代码）：先立基线，编辑后对**每个**目标框架显式构建并跑相关测试（测试命令的隐式构建不算独立构建证据），再跑危险检查。

仓库自带构建/测试文档（`README`/`CONTRIBUTING`、`build.*`、`eng/`、`global.json`、CI workflows）优先于通用命令。否则：

```bash
dotnet build   # 0 errors
dotnet test    # 保持绿；通过数与改前一致
```

一步一个操作；绝不同一步混重构与行为变更。变红即停下报告，只修自己的编辑，不丢弃无关工作区改动。

## 跨边界危险（仅当触及边界时）

变更触及**公共**符号、`InternalsVisibleTo` 友省内成员、**多目标**项目或 partial/生成代码时，部分破坏不会体现为失败测试。先套用范围排除（本地/私有重命名、以及调用方全在项目内的可执行文件公共成员重命名，跳过兼容流程）；否则编辑前启用 breaking-changes 流程（它拥有兼容决策，本技能拥有结构步骤）。搜索仓库找治理该符号的面（别假设）：PublicApiAnalyzers 的 `PublicAPI.Shipped/Unshipped.txt`、`ApiCompat`/`<EnablePackageValidation>`（二者不等价）、`<TargetFrameworks>`/`#if` 分支、`InternalsVisibleTo`。公共类型跨程序集移动需要原程序集 `[TypeForwardedTo]`（同程序集移动不需要）；公共**重命名**需要 `[Obsolete]` shim 而非转发器。

## 停止条件

- 基线本来就红（无法证明行为被保持）。
- 请求的结构变更会破坏公共/已发布 API 且无兼容 shim/转发器可保留——报告边界，不请求做破坏性变更。
- 等价性依赖测试未覆盖的运行时行为（反射、DI、序列化、`dynamic`、P/Invoke）——报告未验证边界，不声称行为被保持。

## 最终回复契约

- **Refactor:** 结构操作名 + 改动的符号/文件。
- **Preserved:** 行为/兼容边界 + 保留机制。
- **Validation:** 精确命令与观察结果；失败后绝不声称成功。
- **Deferred:** 混合请求中被有意推迟的行为/契约变更及其正确后续工作流（无则省略）。
