# GJB 5068 GeoData

面向 GJB 5068-2004 的矢量数据处理与发布工作流。核心原则：先对齐标准的结构与属性，再做格式转换；每一步都能用参考数据做差异验证。

## 使用前提

- 只处理已获授权的数据；遵守数据安全与保密规定，不把涉密坐标、属性、图幅信息写入公开文档或外部服务。
- 先确认标准版本、数据范围、坐标系、目标格式与验收口径。
- 没有参考样本时，先要一份同类型已验收数据做对比基线。

## 交付物

1. 标准拆解表：要素层、几何类型、属性字段、元数据结构
2. XML 配置文件：属性数据格式、元数据模型、区域元数据
3. 转换程序：GeoJSON/OSM → 点/线/面模型 → 目标文件
4. GeoServer 发布配置：工作区、数据存储、图层、图层组、样式、缓存
5. 验证报告：数量、几何、属性、元数据、差异清单

## 工作流

### 1. 数据盘点

- 列出源数据：格式、图层、要素数、坐标系、属性字段、更新时间。
- 标记哪些是基础地理要素、哪些是军事/专题要素。
- 建立文件清单与校验和，后续拷贝、迁移、转换都用同一份清单核对。

### 2. 标准拆解

按 GJB 5068 的要素分类逐项整理：

- 测量控制点
- 道路
- 工农业社会文化设施
- 居民地及附属设施
- 陆地交通
- 管线
- 水域/陆地
- 海底地貌及底质
- 礁石、沉船、障碍物
- 水文
- 陆地地貌及土质
- 要素层、区域、注记
- 军事区域
- 航空要素
- 海上区域界线
- 助航设备及航道
- 地磁要素
- 境界与政区
- 植被

每个要素整理：几何类型、必填属性、可选属性、取值域、单位、编码表、与其他要素的关系。

### 3. 生成 XML 配置

- 属性数据格式：字段名、类型、长度、必填、枚举、默认值。
- 元数据模型：数据集标识、范围、坐标系、精度、生产信息、质量信息。
- 区域元数据：行政区/区域范围、图幅、层级关系。
- 配置必须版本化；每次标准调整都留变更记录。

### 4. GeoJSON 解析

- 读取 FeatureCollection，逐 Feature 判断几何类型。
- 点 → Point / MultiPoint
- 线 → LineString / MultiLineString
- 面 → Polygon / MultiPolygon
- 处理空几何、自相交、重复点、坐标顺序、经纬度范围。
- 先统计各类型数量，再开始转换，避免 silently 丢要素。

### 5. 坐标与属性转换

- 空间坐标：按标准要求的顺序、精度、维度写入；多部件几何要保留部件关系。
- 属性：按 XML 配置做字段映射、类型转换、枚举校验、必填校验。
- 单位与编码：统一单位；编码表外键必须能查到。
- 转换失败要记录要素 id 与原因，不能整批静默跳过。

### 6. 产出目标文件

- 按标准生成点、线、面及多部件模型文件。
- 生成 `.ZB` 等坐标/几何文件时，先小范围试产，再与参考文件逐字节/逐记录对比。
- 生成描述文件与元数据，确保文件之间的引用关系完整。
- 每个产物计算校验和，写入清单。

### 7. 验证

- 数量：源要素数 = 目标要素数（允许明确的过滤规则）。
- 几何：类型、坐标范围、闭合性、自相交、部件数。
- 属性：必填率、枚举合法率、空值率、长度超限。
- 元数据：必填项、范围、坐标系、精度。
- 差异：与参考样本做对称差，逐条解释新增/缺失/变更。
- 发布前再跑一次端到端抽样。

### 8. GeoServer 发布

固定顺序，不可逆：

1. 创建工作区（Workspace）
2. 创建数据存储（DataStore）
3. 发布要素类型/图层（FeatureType/Layer）
4. 配样式（SLD/CSS）
5. 组图层组并设显示规则
6. 设缓存切片
7. 预览与冒烟测试

REST 调用统一用 Basic Auth；MongoDB 数据源需安装与 GeoServer 版本完全一致的 `gs-mongodb-plugin`，`dbtype=mongodb`，几何字段名大小写必须与集合一致，SRS 必须与数据一致。

发布顺序建议：先基础底图（行政区、水系、道路、居民地），再专题层（管线、电网、信号塔、军事区域），最后注记与图层组。图层组显示规则按缩放级别控制，缓存只对稳定图层开启。

详细接口与参数见 `references/geoserver-rest.md`。

## 常见故障

| 现象 | 原因 | 处理 |
|------|------|------|
| 转换后要素变少 | 几何类型不支持/空几何被跳过 | 统计各类型数量，记录跳过原因 |
| 坐标偏移 | 坐标系或轴顺序错误 | 核对 CRS 与经纬度顺序 |
| 属性为空 | 字段映射大小写/编码不一致 | 用配置表逐字段比对 |
| 元数据校验失败 | 必填项缺失或范围不一致 | 补全并重跑校验 |
| GeoServer 无 MongoDB 类型 | 插件缺失或版本不匹配 | 安装对应版本插件并重启 |
| 图层预览无数据 | SRS 不一致/几何字段错/集合为空 | 逐项核对 |
| 切片空白 | 图层组顺序/缩放级别/缓存未 seed | 检查显示规则与缓存任务 |
| 跨服务器拷贝损坏 | 大文件中断/磁盘问题 | 分批拷贝 + 校验和 + 保留 3 份备份 |

## 数据迁移纪律

- 分批拷贝，每批完成后核对文件数与校验和。
- 服务器迁移先备份配置、样式、数据目录，再迁移数据。
- 旧服务文件部分损坏时，优先从备份恢复；没有备份就用参考数据反推配置。
- 任何“重新发布”都要保留旧配置快照，便于回滚。
