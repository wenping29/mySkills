# Tech Tutorial Writer

写一份"读者能照着跑完"的技术教程，而不是资料汇编。核心原则：先声明读者与前置，再按能力梯度拆章节，每个概念配可运行示例与练习。

## 何时使用

- 编程语言/框架/工具的入门教程
- 团队内部培训材料、新人上手文档
- 从零到实战的学习路线
- 已有教程需要补示例、练习、排错

不适用：API 参考手册、源码解析、单篇博客。

## 交付物

1. 教程大纲（章节 + 目标 + 练习）
2. 正文（含可运行代码与预期输出）
3. 练习与验收标准
4. 常见坑与排错表

## 文档结构

```markdown
# 主题教学文档

### TL;DR

3-5 句：它是什么、解决什么问题、学完能做什么、预计多久。

### 元信息

- 目标读者：
- 前置知识：
- 技术栈版本：
- 预计阅读与练习时间：
- 学完能完成的作品：

---

## 第一章 为什么学它

- 痛点对比表
- 与其他方案对比
- 适用/不适用场景

## 第二章 环境搭建

- 安装命令
- 验证命令
- 最小可运行示例

## 第三章 基础概念

- 概念 → 示例 → 输出 → 常见误解

## 第四章 复合能力

- 组合使用
- 边界与坑

## 第五章 工程化

- 包管理/测试/构建/部署

## 第六章 实战项目

- 需求
- 分步实现
- 验收标准

## 附录

- 命令速查
- 常见错误
- 延伸阅读
```

## 章节写作模板

每章按固定节奏：

1. 本章目标（1-2 句）
2. 核心概念（是什么/为什么）
3. 最小示例（可复制运行）
4. 预期输出
5. 变体/进阶
6. 常见坑
7. 练习（1-3 题）
8. 小结（3 条以内）

## 代码示例规则

- 每个示例必须能独立运行；需要多个文件时写清目录结构。
- 标注语言版本与依赖版本；不要用"最新版"。
- 命令给完整形式，不用省略号。
- 给出预期输出；输出可能因平台不同要说明。
- 错误示例要标注"这是错的"，并解释原因。
- 不写伪代码，除非明确标注"伪代码，不可运行"。
- 不引用未验证的第三方库；先确认项目已使用。

## 对比表

适合放对比表的位置：

- 为什么选它：与传统方案对比
- 语言/框架差异：内存、并发、部署、生态
- 适用/不适用：场景清单
- 工具链：命令、用途、替代品

对比维度要具体，避免"更好/更强"。

## 练习设计

每个练习包含：

- 任务描述
- 输入/输出示例
- 验收标准
- 提示（可选）
- 参考答案要点（不直接给完整代码）

练习难度递增：照抄 → 改一处 → 组合 → 独立设计。

## 质量门禁

- [ ] 目标读者与前置写清楚
- [ ] 版本号明确
- [ ] 每章有目标、示例、练习、小结
- [ ] 每个示例可运行，有预期输出
- [ ] 安装/验证命令完整
- [ ] 对比表维度具体
- [ ] 常见坑覆盖真实错误
- [ ] 实战项目有验收标准
- [ ] 没有过时 API
- [ ] 没有"读者自行补充"的关键步骤
- [ ] 全文命令可复制粘贴执行

## 写作风格

- 先给结论，再解释。
- 一段只讲一个点。
- 术语第一次出现给定义。
- 用表格压缩对比信息。
- 用"你"称呼读者，少用"我们"。
- 不写鸡汤，不写"众所周知"。
- 复杂概念用类比，但类比后要回到准确表述。
