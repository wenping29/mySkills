# AI Daily Brief

把一天的信息噪音压成一份可读、可追溯、不重复的 AI 情报简报。核心原则：先核验，再判断；数字带口径，观点带保留；同一件事只取新角度。

## 何时使用

- 每日/每周 AI 行业简报
- 模型发布、开源权重、基准、定价跟踪
- 具身智能、融资并购、政策安全动态
- 免费额度、折扣、临期优惠速报

不适用：单篇深度技术评测、纯论文解读、投资建议。

## 关注范围

默认四条线，可按用户调整：

1. AI coding / Agent / 开发工具
2. 大模型发布、开源权重、上下文、基准
3. 具身智能 / 机器人 / 硬件
4. 融资并购 / 商业化 / 免费与优惠

## 编辑流程

1. 收集：官方博客、模型卡、GitHub/Hugging Face、监管公告、可信媒体。
2. 交叉核验：至少两个独立来源；厂商自测单独标注。
3. 分级：今日主线 1 条，主条目 4-6 条，短讯 4-8 条。
4. 写：事件 → 为什么值得关注 → 保留意见。
5. 去重：对照最近 N 期，只保留新事实或新角度。
6. 跟进：列出下期要验证的承诺、日期、数字。

## 核验规则

1. "承诺开源/发布"以仓库实查为准，不以博客、媒体转述为准。
2. 官方自测基准必须标注"官方自测，待第三方复现"。
3. 销量、好评率、估值、融资额必须带统计口径与截止日期。
4. 区分事实、推断、传闻；传闻必须写"未证实"。
5. 媒体抢跑要纠偏：写明"此前报道 vs 实际"。
6. 优惠信息以官方活动页二次确认；二手清单可能过期。
7. 同一事件出现多个数字时，并列口径，不强行选一个。
8. 不用厂商宣传语替代判断；"最强/第一"要加限定与来源。

## 文章结构

```markdown
# AI 每日重要动态 · YYYY-MM-DD

> 关注方向：……
> 本期 N 条主条目 + M 条短讯

## 今日主线：一句话定性

2-4 段，解释今天为什么是这一天，和前期预告/跟进的关系。

---

## 一、分类：标题（一句话结论）

**事件**
- 关键数字/时间/主体
- 关键动作
- 关键限制

**为什么值得关注**
- 对行业意味着什么
- 对用户/企业意味着什么
- 与前期主线的关系

**保留意见**
- 未证实/未公布/口径问题

---

## 短讯

- 每条 1-3 句，含主体 + 数字 + 意义

---

## 去重说明

本期与 X 期无重复；逐条说明哪些是旧事新角度，哪些是首次推送。

## 下期跟进

① …… ② …… ③ ……
```

## 写作规则

- 标题给结论，不写"某公司发布某产品"这种无信息标题。
- 每条至少一个可验证数字；没有数字就写清"未披露"。
- "为什么值得关注"要写传导链：事件 → 行业 → 用户/企业。
- 保留意见不是客套，要写具体的未知项与风险。
- 与上期对比：新增了什么、兑现了什么、打脸了什么。
- 优惠条目写清：原价、折后价、有效期、适用条件、是否自动续费。
- 短讯只留"有信息增量"的，不做新闻联播。
- 全文避免形容词堆砌；用数字和动作说话。

## 去重台账

维护一张滚动表：

| 日期 | 主体 | 事件 | 已写角度 | 下次可用角度 |
|------|------|------|----------|--------------|

规则：

- 同一事件同一角度不重复写。
- 新角度包括：兑现/延期、数字更新、监管变化、竞争反应、价格变化。
- 去重说明要能让读者看出"这期为什么还值得看"。

## 质量检查

- [ ] 今日主线只有一条，且能一句话说清
- [ ] 每条主条目有事件、意义、保留意见
- [ ] 每个关键数字有口径与日期
- [ ] 官方自测已标注
- [ ] 承诺类信息已实查
- [ ] 与最近 N 期无重复角度
- [ ] 去重说明逐条可追溯
- [ ] 下期跟进有具体验证对象
- [ ] 优惠信息有有效期与条件
- [ ] 没有把厂商稿当事实
